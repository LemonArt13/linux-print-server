# Короткий звіт до дипломної роботи

## Тема

**«Розробка веборієнтованої системи централізованого керування друком документів у локальній мережі».**

## Актуальність

У невеликих навчальних аудиторіях та офісах часто використовується звичайний USB-принтер, який не має Wi‑Fi або мережевого інтерфейсу. Для друку з кількох комп’ютерів необхідно підключати принтер до одного комп’ютера-сервера та надати користувачам простий вебінтерфейс. Це дає змогу централізовано приймати документи, бачити стан черги й вести історію друку.

## Мета роботи

Створити вебзастосунок, через який користувачі локальної мережі можуть завантажувати PDF-документи до спільної черги друку, а адміністратор — переглядати історію та керувати її зберіганням.

## Що реалізовано на поточному етапі

- вебклієнт українською мовою на React і Material UI;
- головна сторінка зі станом принтера, формою завантаження й таблицею черги;
- одночасне завантаження до 10 PDF-файлів;
- перевірка розширення, MIME-типу, PDF-сигнатури та розміру файлу до 10 МБ;
- демонстраційна черга: завдання послідовно переходять зі стану «У черзі» у «Друкується» та «Завершено»;
- можливість скасувати завдання;
- коректне відображення назв файлів українською мовою;
- сторінка адміністратора `/admin` із входом за паролем;
- зберігання хешу пароля у змінній середовища, без зберігання відкритого пароля в коді;
- захищені адміністративні API;
- історія друку у файлі `print-history.txt` та налаштування у `settings.json`;
- завантаження історії як TXT-файлу, ручне очищення й автоматичне очищення записів старше 7, 30 або 90 днів.

## Використані технології

| Частина системи | Технології |
|---|---|
| Клієнтська частина | React, Vite, JavaScript, React Router |
| Інтерфейс | Material UI |
| Серверна частина | Node.js, Express |
| Завантаження файлів | Multer |
| Зберігання даних | TXT-файл і JSON-файл |

## Спрощена архітектура

```text
Користувач у локальній мережі
            │
            ▼
React-клієнт → Express REST API → Сервіс черги друку
                                      │
                                      ├── тимчасові PDF-файли
                                      ├── print-history.txt
                                      └── settings.json
```

Сервіс черги друку винесено в окремий модуль. Тому логіку імітації можна замінити на реальний виклик системи друку без значних змін у клієнтській частині та REST API.

## Що буде реалізовано на наступному етапі

- встановлення й налаштування CUPS на Linux-сервері;
- підключення USB-принтера до CUPS;
- заміна демонстраційної затримки на реальне надсилання PDF у CUPS командою `lp` або через API CUPS;
- отримання реального стану принтера й помилок друку;
- запуск сервера в локальній мережі та перевірка доступу з інших пристроїв;
- за потреби — вдосконалення авторизації та журналювання помилок.

## Висновок

На першому етапі створено працездатний прототип веборієнтованої системи централізованого керування друком. Він демонструє основний користувацький сценарій: вибір PDF-документів, їх додавання до черги, відображення статусів та адміністрування історії. Обрана структура є простою для пояснення на захисті та водночас дозволяє надалі інтегрувати реальний друк через CUPS.
