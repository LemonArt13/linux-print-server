# Централізоване керування друком — прототип

Початковий прототип до дипломної роботи «Розробка веборієнтованої системи централізованого керування друком документів у локальній мережі».

Це демонстраційний застосунок: він приймає PDF-файли, послідовно змінює стани завдань у черзі та веде історію. Фізичний друк і CUPS на цьому етапі не використовуються.

## Структура

- `client` — React + Vite + Material UI + TypeScript, інтерфейс українською мовою.
- `server` — мінімальний Express REST API на TypeScript.
- `server/src/printService.js` — незалежний демонстраційний сервіс черги; надалі тут можна підключити CUPS.
- `server/data/print-history.txt` — історія друку у форматі JSON-рядків у звичайному TXT-файлі (створюється автоматично).
- `server/data/settings.json` — налаштування автоматичного очищення (створюється автоматично).
- `client/src/styles.ts` — усі стилі інтерфейсу та налаштування теми Material UI.

## Вимоги

- Node.js 20 або новіший;
- npm 10 або новіший.

## Запуск

1. Встановіть залежності в корені проєкту:

   ```bash
   npm install
   npm run install:all
   ```

2. Створіть файл конфігурації сервера:

   ```bash
   cp server/.env.example server/.env
   ```

3. Задайте у `server/.env` SHA-256 хеш пароля адміністратора. Наприклад, для створення хешу:

   ```bash
   node -e "console.log(require('crypto').createHash('sha256').update('мій-пароль').digest('hex'))"
   ```

   Скопіюйте результат після `ADMIN_PASSWORD_HASH=`. Сам пароль у файлі не зберігається.

4. Запустіть клієнт і сервер однією командою:

   ```bash
   npm run dev
   ```

5. Відкрийте [http://localhost:5173](http://localhost:5173). API доступне на `http://localhost:4000`.

Або запустіть складові окремо:

```bash
npm run dev --prefix server
npm run dev --prefix client
```

Для перевірки TypeScript-коду та production-збірки:

```bash
npm run build --prefix server
npm run build --prefix client
```

## Реалізована функціональність

- адаптивна головна сторінка з MUI-компонентами та навігацією;
- індикатор стану демонстраційного принтера;
- одночасне завантаження від 1 до 10 PDF-файлів: перевіряються MIME/розширення, сигнатура `%PDF-` та обмеження 10 МБ на файл;
- тимчасовий файл завантаження видаляється після завершення або скасування завдання;
- демонстраційна послідовна черга зі станами «У черзі», «Друкується», «Завершено», «Скасовано»;
- скасування активних та очікуваних завдань;
- `/admin` із входом за паролем: на сервер передається пароль, сервер порівнює його SHA-256 хеш зі значенням змінної середовища та видає короткочасний токен поточної сесії;
- захищені адміністративні API для перегляду, завантаження та очищення історії, а також налаштувань;
- автоматичне очищення тільки записів історії, старших за 7, 30 або 90 днів. Поточна черга при цьому не змінюється.

## REST API

| Метод | Шлях | Призначення |
|---|---|---|
| `GET` | `/api/health` | Стан демонстраційного принтера |
| `GET` | `/api/jobs` | Поточна черга |
| `POST` | `/api/jobs` | Додати PDF-файли (`multipart/form-data`, поле `documents`) |
| `DELETE` | `/api/jobs/:id` | Скасувати завдання |
| `POST` | `/api/admin/login` | Отримати адміністративний токен |
| `GET`, `DELETE` | `/api/admin/history` | Переглянути або очистити історію |
| `GET` | `/api/admin/history/download` | Завантажити TXT-файл історії |
| `GET`, `PUT` | `/api/admin/settings` | Переглянути або змінити налаштування |

## Наступний етап

Для реального друку потрібно замінити затримку в `server/src/printService.js` на виклик CUPS (наприклад, `lp`), зберігши поточний контракт черги й API. Авторизація в прототипі навмисно мінімальна: токени зберігаються тільки в пам’яті сервера і скидаються після його перезапуску.
