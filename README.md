# PrintFlow — прототип для передзахисту

Тема: «Розробка веборієнтованої системи керування друком документів на базі Linux-сервера».

Застосунок приймає й зберігає PDF, реєструє їх у журналі та має адміністративний інтерфейс. Статус нових документів — «Очікує налаштування друку». **Фізичний друк та інтеграція з CUPS ще не реалізовані.** Старі completed/printing/queued записи позначені як архів імітації.

## Локальний запуск

Використовується Node.js 24 LTS. Залежності встановлюються окремо для кожної ОС:

```bash
npm ci
npm ci --prefix client
npm ci --prefix server
# Лише якщо server/.env ще немає:
cp -n server/.env.example server/.env
python3 scripts/set-admin-password.py server/.env
npm run dev
```

Адреса розробки: http://127.0.0.1:5173, API через Vite proxy `/api` → порт 4000. Production:

```bash
npm run build
npm run typecheck
npm test
npm start
```

Production frontend та API працюють з одного origin: http://127.0.0.1:4000. Маршрут `/admin` підтримує пряме відкриття. Для Ubuntu задається `HOST=0.0.0.0`. Невідомі API-маршрути повертають JSON 404.

## Розгортання Ubuntu

Повна інструкція налаштування, запуску й діагностики: [UBUNTU_SERVER_GUIDE.md](UBUNTU_SERVER_GUIDE.md).

1. Додати публічний SSH-ключ Mac до `~/.ssh/authorized_keys` користувача Ubuntu.
2. Переглянути `deploy/bootstrap-ubuntu.sh`, передати його разом із `deploy/printflow.service` на Ubuntu. Виконати `sudo bash /home/artem/bootstrap-ubuntu.sh artem`. Скрипт призначений для наявної Ubuntu 26.10, де apt надає Node.js 24. Він не перевстановлює ОС.
3. Створити на Ubuntu окремий SSH deploy key, додати до існуючого приватного GitHub-репозиторію з вимкненим Allow write access. Перевірити ключ хоста GitHub за офіційним джерелом, використати `IdentityFile` і `IdentitiesOnly yes`.
4. Клонувати код у `/opt/printflow/repo` через SSH; запустити `bash /opt/printflow/repo/deploy.sh` від користувача розгортання.
5. Перевірити `systemctl status printflow.service`, `curl http://127.0.0.1:4000/api/health`, потім відкрити адресу Ubuntu з Mac.

`deploy.sh` використовує `git pull --ff-only`, встановлює Linux-залежності через npm ci та збирає окремий release до перемикання `current`. Дані й секрети розміщені поза checkout. При невдалій health-перевірці відновлюється попередній release. Старі releases не видаляються автоматично. Служба працює як непривілейований `printflow`. Право sudo користувача розгортання обмежене restart/stop цієї служби.

Конфігурація: `/etc/printflow.env` (root, 0600). Перший випадковий пароль адміністратора зберігається локально в `/home/artem/.config/printflow/initial-password` (0600), не в Git. Для зміни: `sudo python3 scripts/set-admin-password.py /etc/printflow.env`, після цього перезапустити службу. Не виводити пароль на скриншотах.

## Мережа та межі демонстрації

Поточна адреса Ubuntu в Parallels Shared Network: `10.211.55.10`. Після успішного розгортання адреса сайту: `http://10.211.55.10:4000`. Shared Network утворює приватну підмережу Mac–VM. Пряма доступність цієї адреси з телефона не гарантується. Для телефона потрібен погоджений Bridged Network у довіреній локальній мережі та повторна перевірка IP/firewall. Публічні порти роутера не налаштовуються.

## Дані й обмеження

- `DATA_DIR`, `UPLOAD_DIR` задають каталоги даних; локально це server/data і server/uploads.
- До 10 PDF по 10 МБ. Перевірка `%PDF-` не є повним аналізом документа або антивірусом.
- PDF зберігаються під UUID з правами 0600. Після кінцевого результату друку (`completed`, `error`, `cancelled`) файл видаляється, а запис історії залишається. Майбутній обробник друку має викликати `finishPrintJob` після підтвердження кінцевого стану принтером. Невдалі видалення повторюються щохвилини та після перезапуску сервера. Документи в очікуванні, зокрема `awaiting_setup`, зберігаються; фізичний друк ще не підключений, тому нові завантаження поки залишаються на диску. Очищення журналу саме по собі не видаляє PDF завдань в очікуванні.
- Журнал TXT містить JSON Lines; записи зберігаються атомарною заміною файла. Один серверний процес, без БД та кластера.
- Успішна HTTP-відповідь означає реєстрацію документа, а не друк.
- Адміністративні сесії мають строк дії, відкликаються при виході та скидаються після перезапуску. Нові паролі — scrypt; старі SHA-256 хеші підтримуються для сумісності.
- Користувач бачить записи за випадковими UUID своєї вкладки. Це не повноцінні облікові записи та не сувора ізоляція користувачів.
- Поточна HTTP-демонстрація призначена для довіреної локальної мережі; перед ширшим використанням потрібні HTTPS, квоти, політика видалення PDF та посилення контролю доступу.

## API

| Метод | Маршрут | Результат |
|---|---|---|
| GET | /api/health | Стан сервера, printingEnabled: false |
| POST | /api/jobs | Прийняти PDF у полі documents |
| GET | /api/jobs?ids=UUID,... | Записи за відомими ідентифікаторами |
| POST | /api/admin/login | Адміністративна сесія |
| POST | /api/admin/logout | Відкликати сесію |
| GET, DELETE | /api/admin/history | Переглянути/очистити журнал |
| GET | /api/admin/history/download | TXT-експорт |
| GET, PUT | /api/admin/settings | Параметри очищення журналу |

Актуальні результати: `PROJECT_PROGRESS.md`, `report/TEST_RESULTS.md`. Старі матеріали `Документація_проєкту.md`, `Звіт_для_захисту.md` і старий DOCX описують попередню імітацію; актуальний звіт міститься у `report/Передзахист_дипломної.docx` та PDF.
