## Код і документація

Основна інструкція — [UBUNTU_SERVER_GUIDE.md](../UBUNTU_SERVER_GUIDE.md): 12 послідовних кроків від нової Ubuntu до ручного запуску, LAN, systemd, підготовки CUPS, оновлення та діагностики. README скорочено до опису, швидкого запуску й посилання на цю інструкцію. Альтернативних повних інструкцій немає.

Фронтенд не змінювався. У сервері прибрано невикористані залежності `cors` і `@types/cors` та зайві записи lock-файла. API вже працює з тієї самої адреси, а режим розробки використовує proxy Vite, тому ця залежність не потрібна. Авторизацію, перевірку PDF та підготовлену функцію `finishPrintJob` залишено.

Два невеликі виправлення:

1. Автоматичне очищення за віком тепер зберігає записи незавершених документів, щоб не залишати PDF в очікуванні без запису для майбутнього обробника друку. Ручне очищення всього журналу зберігає свою попередню поведінку.
2. Переміщений PDF одразу включається до списку для відкату: якщо зміна його прав завершиться помилкою, файл теж буде прибраний як частина невдалого завантаження.

`npm run install:all` тепер виконує `npm ci` для client і server, відтворюючи залежності за lock-файлами. Схему release/current і відкат у `deploy.sh` збережено; шлях `/opt/printflow/current/server/dist/index.js` відповідає unit і збірці.

## Що ще перевірити вручну

- Повне встановлення за інструкцією на **чистій Ubuntu 24.04 LTS**, включно з apt, NodeSource, ключем GitHub і першим клонуванням. Інструкція звірена з кодом та офіційною документацією, але повне розгортання з нуля в цьому сеансі не виконувалося.
- Початкове створення користувача й каталогів служби, встановлення unit та `/etc/printflow.env`, перше розгортання через `deploy.sh`. Справжню службу не перевстановлювали.
- Повне перезавантаження Ubuntu та запуск служби після нього; увімкнення самої VM окреме від `systemctl enable`.
- Bridged Network, правильну адресу LAN, правила UFW і доступ із фізичного телефона або другого ноутбука. HTTP Mac–VM перевірено, телефон — ні.
- Відновлення резервної копії, збій оновлення з відкатом, нестачу диска, навантаження та всі граничні значення розміру й кількості файлів.
- Остаточний вигляд DOCX на комп'ютері викладача та локальні вимоги кафедри. Поточний PDF уже має перевірений обсяг і зберігає розмітку сторінок.

Для завершення CUPS потрібні конкретний принтер, передавання USB у VM, сумісний драйвер і черга, окрема перевірка друку з `lp`, а потім реалізація передавання PDF з вебсервера, збереження ідентифікатора CUPS та отримання кінцевих станів. Фізичний друк у цій підготовці не виконувався.
