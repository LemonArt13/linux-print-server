# Скриншоти передзахисту

Стан: 13.11.2026. У звіт уже вставлено **шість справжніх скриншотів**: чотири з консолі Ubuntu у Parallels і два з браузера Mac, який звертався до IP Ubuntu. `assets/architecture.png` — пояснювальна схема, а не скриншот. Оригінали збережено без вигаданого вмісту; у DOCX для термінала застосовано лише кадрування порожньої нижньої ділянки засобами верстки.

Скриншоти браузера зроблені Playwright зі встановленим Google Chrome в headless-режимі. Адресний рядок у такому знімку не відображається. Фактична адреса переходу `http://10.211.55.10:4000` і результати перевірки зафіксовані у `browser-results.json`. Для наочного показу адресного рядка можна додатково зробити ручний скриншот звичайного браузера.

Не відкривайте під час зйомки `.env`, `initial-password`, приватні SSH-ключі, токени або приватні документи. IP та публічний ключ не є паролем, але для звіту достатньо показаних команд без секретів.

## Рисунок 3.1 — Підготовлене середовище Ubuntu Server у Parallels

- Файл: `screenshots/02-ubuntu-prepared.png` — уже створено.
- Відкрити: консоль наявної VM **Ubuntu Linux** у Parallels Desktop.
- Команди: `clear`, `cat /etc/os-release | head -3`, `uname -m`, `node -v`, `npm -v`, `systemctl is-active ssh cups`.
- Має бути видно: Ubuntu 26.10, aarch64, версії Node/npm та активність служб.
- Місце: підрозділ 3.1, після опису встановлення пакетів.
- Підпис: «Рисунок 3.1 — Підготовлене середовище Ubuntu Server у Parallels».

Знімок показує фактичне гостьове середовище, у якому запускається сервер. Він відрізняє Ubuntu від macOS та підтверджує наявність потрібного runtime. Установлення CUPS на цьому знімку не означає підключення принтера або виконання друку.

## Рисунок 3.2 — IP-адреса Ubuntu та мережевий порт вебзастосунку

- Файл: `screenshots/03-ubuntu-ip.png` — уже створено.
- Відкрити: консоль Ubuntu.
- Команди: `clear`, `hostname`, `ip -br a`, `ip route`, `ss -ltn 'sport = :4000'`.
- Має бути видно: enp0s5, адресу `10.211.55.10/24`, маршрут та `0.0.0.0:4000`.
- Місце: підрозділ 3.2, після опису Shared Network.
- Підпис: «Рисунок 3.2 — IP-адреса Ubuntu та мережевий порт вебзастосунку».

IP використовується браузером Mac як адреса сервера. Прослуховування 0.0.0.0:4000 підтверджує, що процес приймає IPv4-з’єднання через мережевий інтерфейс. Сам знімок адреси ще не доводить відкриття сайту: це окремо перевірено HTTP та браузером.

## Рисунок 3.4 — Активна systemd-служба PrintFlow та відповідь API

- Файл: `screenshots/05-systemd-service.png` — уже створено.
- Відкрити: консоль Ubuntu.
- Команди: `clear`, `systemctl status printflow.service --no-pager`, `systemctl is-enabled printflow.service`, `curl -s http://127.0.0.1:4000/api/health`.
- Має бути видно: active (running), enabled, процес Node та `printingEnabled:false`.
- Місце: підрозділ 3.4.
- Підпис: «Рисунок 3.4 — Активна systemd-служба PrintFlow та відповідь API».

Служба працює незалежно від SSH-сесії та запускає активну production-збірку. Статус enabled підтверджує налаштування автозапуску, але повний reboot VM окремо не тестувався. JSON стану явно розмежовує готовність HTTP-сервера й відсутність фізичного друку.

## Рисунок 3.5 — Сайт Ubuntu, відкритий у браузері на Mac

- Файл: `screenshots/06-ubuntu-site-from-mac.png` — уже створено.
- Відкрити: Chrome/Safari на Mac, `http://10.211.55.10:4000`.
- За потреби запустити з термінала: `open http://10.211.55.10:4000`.
- Має бути видно: головну сторінку та «Сервер доступний», для ручного знімка також адресний рядок.
- Місце: підрозділ 3.5, після HTTP-перевірки.
- Підпис: «Рисунок 3.5 — Сайт Ubuntu, відкритий у браузері на Mac».

Це головний доказ сценарію передзахисту: браузер працює на Mac, а сторінку та API надає Ubuntu. Перевірка очікувала індикатора доступності сервера й не зафіксувала pageerror або requestfailed. Це не є доказом доступу з телефона або фізичного друку.

Автоматичний знімок IDE не включений у звіт, оскільки наявного безпечного інструмента захоплення цього вікна не використано.

## Додатково: телефон у локальній мережі

- Файл після реальної перевірки: `screenshots/08-phone-lan.png` — не створений.
- Потрібна узгоджена мережа Bridged або інший перевірений маршрут до VM; зараз Shared.
- На Ubuntu: `ip -br a`. На телефоні у тій самій LAN відкрити `http://НОВА_IP_UBUNTU:4000`.
- Місце після перевірки: підрозділ 3.5 або додаток А; додати посилання й підпис «Рисунок А.2 — Доступ до вебзастосунку з телефона в локальній мережі».

Телефон перевіряє окремий мережевий шлях, який не доводиться відкриттям сайту з Mac. Після зміни режиму необхідно повторно перевірити адресу й firewall. До фактичного відкриття сторінки цей результат у звіті позначається як невиконаний, а місце зображення не заповнюється імітацією.
